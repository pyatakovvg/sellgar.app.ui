# Collector

`CollectorInterface<TItem, TState>` — абстрактный класс для внедрения накопителя
массива. Реализация `Collector<TItem, TState>` выполняет переданный callback через
`execute()` и возвращает его результат `TItem[]`.

В controller накопитель внедряется специализированным декоратором. Ключ
определяется рядом с зависимостью:

```ts
constructor(
  @InjectCollector('operations')
  private readonly collector: CollectorInterface<OperationEntity, OperationCollectionState>,
) {}
```

`InjectCollector` совмещает внедрение абстрактного порта и конфигурацию ключа.
Framework создаёт отдельный transient `Collector` для каждого параметра.
Feature не регистрирует его в bindings и не вызывает `register` или cleanup.
Публичные имена не пересекаются: `Collector` — класс, `CollectorInterface` —
абстрактный контракт, `InjectCollector` — декоратор. Прямое создание
`new Collector()` сохраняется для работы вне runtime и изолированных тестов.

Контроллеры поиска и фильтров получают отдельный сервис адресного сброса:

```ts
constructor(
  @Inject(CollectorServiceInterface)
  private readonly collectorService: CollectorServiceInterface,
) {}

async setSearch(search: SearchDto): Promise<void> {
  this.collectorService.reset('operations');
  await this.query.set(SearchDto, search);
}
```

Сервис сбрасывает только явно указанный ключ и не запускает загрузку.
Собственный накопитель controller сбрасывает через `collector.reset()`.
Сервис не создаёт дополнительный накопитель и не зависит от RevalidateService.

Ключ — непустая строка в пределах конкретного живого runtime Module, Widget
или Application controllers. Одинаковые ключи в разных runtime независимы.
Повторный живой ключ и сброс неизвестного ключа завершаются ошибкой. Поиска
в родительском runtime и отложенного создания коллектора нет.

Регистрация принадлежит экземпляру controller. При фактической выгрузке
framework отзывает доступ сервиса, снимает регистрации и полностью очищает
строки, состояние и ссылки накопителя на текущую задачу. Запоздалый результат
не восстанавливает данные; поздний cleanup не удаляет новую регистрацию того
же ключа. Ошибка конструктора откатывает уже созданные ресурсы. Ошибка
пользовательского `dispose()` не препятствует очистке. Скрытый/retained runtime
и сохранённый для retry runtime продолжают владеть своими ресурсами.

Декоратор применяется к параметру конструктора runtime-controller. Коллектор
или сервис, захваченный повторно используемым controller с завершённым
lifecycle, не присоединяется автоматически к новому владельцу.

```ts
return collector.execute(async (collection, state) => {
  const response = await service.read(state.get('position'));
  state.set('position', response.continuation);
  return collection.append(response.records);
});
```

`collection.append(items)` добавляет элементы в порядке поступления и возвращает
накопленный массив. Поля ответа, уникальность записей, фильтры, позиции запросов
и правила завершения определяет потребитель. Пустой массив не означает конец.

Второй аргумент `state` предоставляет типизированные `get(key)` и
`set(key, value)`. Имена ключей и типы значений задаёт `TState`. Чтение
неустановленного ключа возвращает `undefined`. Значения заменяются через `set`;
вложенные объекты следует считать неизменяемыми, а не мутировать результат `get`.
`collector.state.get(key)` читает только подтверждённые значения. Снаружи
callback состояние недоступно для записи.

`reset()` запрашивает начало новой коллекции с пустым управляемым состоянием.
До успешной загрузки подтверждённый массив и значения сохраняются. После ошибки
сброс остаётся ожидающим. Выполняющаяся или подготовленная loader-транзакция
накопителя отменяется: новая загрузка не ждёт завершения устаревшего callback.
Результат запроса, начатого до reset, не принимается.

Если запрос ревалидации присоединился к прерванной загрузке, runtime выполняет
его после освобождения прежней операции. Успешные совпадающие загрузки остаются
объединёнными; уже подтверждённые независимые targeted-загрузки не повторяются.
Запрос после отмены его signal, смены сессии или освобождения владельца не
возобновляется. Обычная ошибка загрузки не запускает автоматический retry.

При повторном явном входе в раздел navigation runtime начинает новую выборку
только у целевого владельца, если для него запланирована ревалидация. Collector
сравнивает поколение выборки своей loader-транзакции с подтверждённым поколением.
Первый callback новой выборки получает пустые массив и state; старые данные
сохраняются до успешной публикации. Ошибка оставляет новую выборку ожидающей,
поэтому обычный retry начинает её с начала. Старые выполняющиеся и ожидающие
запросы не могут опубликовать результат в новое поколение.

Дозагрузка, query-ревалидация и восстановление retained activation не начинают
новую выборку автоматически. `revalidate: false` не меняет её поколение.
Открытие/закрытие дочерней ветки не сбрасывает родительские коллекции. Неизвестный
внешний restore не трактуется как явный повторный вход. Навигационный контекст
не распространяется автоматически на независимые Widget owners.

Одинаковые конкурентные вызовы внутри одной операции используют один promise;
после reset начинается новая операция. Каждый успешный append создаёт новый
массив. Изменение возвращённого массива не меняет внутреннее накопление.

Без runtime (`new Collector()`) изменения подтверждаются после успешного
callback. При injection в Module/Widget/Application scope действует общая
транзакция loader data: массив и значения подтверждаются вместе с принятием
результата runtime. Ошибка другого loader/provider, supersede, abort и dispose
отбрасывают подготовленные изменения. Controller не вызывает commit/rollback
и не перехватывает ошибки для записи собственных process/error flags.

Collector регистрируется без singleton: каждое внедрение получает отдельный
экземпляр. Накоплением и сбросом управляет controller-владелец коллекции.
Request scope для накопителя также не используется: два параметра одного
конструктора должны получать разные экземпляры. Адресный сброс сохраняет
атомарность существующей loader-транзакции: подтверждённое состояние других
коллекторов сохраняется, но подготовленная общая транзакция может быть
отклонена целиком. Сброс запрещает публикацию старого результата; физическая
отмена произвольного callback не является частью API накопителя.
Тесты `collector.test.ts` покрывают разные контракты источников и накопление;
`collector-runtime.test.ts` проверяет совместную фиксацию массива и состояния
в настоящих Module и Widget runtime.
