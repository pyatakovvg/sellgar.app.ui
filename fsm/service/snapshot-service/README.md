# SnapshotService

`SnapshotServiceInterface` зарегистрирован в application scope FSM-среза.
`get(Token)` возвращает экземпляр класса из текущего committed snapshot либо
`null`, если снапшота или объекта нет. До первого commit результат — `null`.
Pending snapshot нового маршрута не подменяет данные приложения до commit.

Токен — сам класс модели, включая вложенные модели. Поиск использует точную
идентичность класса, не название поля или класса. Данные уже преобразованы и
проверены источником; сервис не создаёт экземпляры и не хранит копии снапшота.
Framework не знает прикладных полей `ui`, `profile`, `wallet` и `balance`.

Разные экземпляры одного класса в текущем дереве делают токен неоднозначным:
сервис выбрасывает ошибку вместо выбора первого совпадения. Повторные ссылки
на один объект допустимы. Computed getters не выполняются.

`ScreenServiceInterface` остаётся route-scoped: предоставляет state и commands
экранного токена, в том числе pending state для loader нового маршрута.

## Подписка

`subscribe(Token, listener)` использует существующие уведомления application
location о committed snapshot и передаёт результат `get(Token)` — тот же
проверенный экземпляр или `null`. Pending snapshot не публикуется.
Отдельного хранилища, копий данных и event bus сервис не создаёт.

Подписка не вызывает listener немедленно. Для начальной синхронизации сначала
установить подписку, затем прочитать `get(Token)`. До первого снапшота это `null`;
ожидать первый снапшот в startup loader/provider не требуется.

Каждое уведомление location вызывает listener, даже если экземпляр токена не
изменился. Отсутствие объекта в новом снапшоте передаётся как `null`, а
неоднозначность токена сохраняет ошибку `get`, не подменяя её отсутствием данных.
Возвращаемая функция снимает только эту подписку; повторный cleanup безопасен.
Освобождение подписки принадлежит вызывающему runtime owner.

React hooks и перенос translation runtime не входят в этот API.
