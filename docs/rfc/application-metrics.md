# RFC: Подсистема метрик приложения

- Статус документа: historical
- Статус RFC: accepted
- Статус реализации: implemented
- Основание: согласованный с владельцем контракт и явный запрос реализации.
- Текущий контракт: [метрики приложения](../../core/application/metric/README.md).
- Исполнение и проверки: [implementation handoff](../application-metrics-implementation.md#current-handoff).

## Принятое решение

В framework добавлена самостоятельная роль `Metric` с application-scoped
сервисом и lifecycle. Прикладной API принимает class token события и
типизированные данные; адаптер получает имя из `@MetricEvent` и payload
валидированного события. View и controllers используют один сервис.

Получатели выбираются в `metric.track(Event, data, { to })`, а не списками
событий в конфигурации приложения. Без `to` событие передаётся всем. Настроенный
adapter token сохраняет identity исходного класса; один класс имеет один
экземпляр на приложение.

Core владеет ограниченной FIFO-очередью из 150 ожидающих записей на получателя,
независимой инициализацией, изоляцией ошибок через reporter и bounded shutdown
за 2 секунды. Классы событий объявляют поля с `!`, без `declare`, позиционных
конструкторов, обязательного `@Expose()` и имени в payload.

## Сознательно исключено из первой версии

Повторы, анализ HTTP-кодов, network-status tracking и offline-восстановление
отклонены владельцем как избыточная сложность первой версии. Нет persistent
queue, нескольких подключений одного класса, отдельного pageView и
автоматической регистрации просмотров. Конкретные Яндекс/Matomo SDK adapters
относятся к последующим интеграциям, не к framework outcome.

Исходный проект и этапы сохранены в Git; действующий public/runtime contract
принадлежит current-документу владельца, а результаты проверок — handoff.
